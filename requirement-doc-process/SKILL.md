# 需求文档处理规范

## 概述

处理包含图片的需求文档（Word格式），将文档内容和图片分离，生成便于开发使用的任务拆分文档。

## 适用场景

当用户提供了包含图片的需求文档（.docx格式），需要进行需求分析和任务拆分时使用。

## 处理流程

### 步骤1：准备工作目录

**优先级：必做**

在项目的 `docs/` 目录下创建本次需求的文件夹，命名格式：`版本号+模块名称+需求变更`

```
示例：docs/6.10工程项目管理模块需求变更/
```

在该文件夹下创建 `images/` 子目录，用于存放从文档中提取的图片。

**目录结构：**
```
docs/
└── 6.10工程项目管理模块需求变更/
    ├── images/
    │   ├── image_1.png
    │   ├── image_2.png
    │   └── ...
    ├── 需求文档_图文对应.md
    └── 需求文档_按开发顺序整理.md
    └── 任务拆分.md
```

### 步骤2：提取图片并生成图文对应文档

**优先级：必做**

从Word文档中提取所有内容，**严格按照原文档的顺序**，将文字和图片一一对应，生成 `需求文档_图文对应.md`。

**关键要求：**
- ✅ 图片按原始出现顺序命名：`image_1.png`, `image_2.png`, ...
- ✅ 文字和图片的位置关系必须与原Word文档完全一致
- ✅ 不遗漏任何文字段落或图片
- ✅ 不改变原文的表述
- ✅ 表格也要完整保留

### 步骤3：生成按开发顺序整理的需求文档

**优先级：必做**

基于 `需求文档_图文对应.md`，重新整理成便于开发的格式，生成 `需求文档_按开发顺序整理.md`。

**文档结构要求：**

```markdown
# 6.10 工程项目管理模块需求变更

## 📋 需求总览
| 序号 | 需求名称 | 涉及模块 | 状态 |
|------|----------|----------|------|
| 1 | xxx | 费用申请 | 待开发 |
| ... | ... | ... | ... |

---

## 🔍 详细需求

### ✅ 需求 1：xxx

**需求描述：**
> 引用原文描述

**涉及文件：**
- `src/views/xxx/xxx.vue`

**修改内容：**
1. 具体修改点1
2. 具体修改点2

**需求截图：**
![xxx](images/image_1.png)

---

### ✅ 需求 2：xxx
...
```

**整理原则：**
1. 将大段需求拆分成可独立开发的小任务（每条开发时间建议1-4小时）
2. 按开发依赖关系排序（先改基础功能，后改复杂功能）
3. 每条需求明确：需求描述、涉及文件、修改内容、对应截图
4. 合并重复的需求点

### 步骤4：生成任务拆分文档

**优先级：必做**

生成 `任务拆分.md`，便于团队协作和进度跟踪。

**任务拆分原则：**
- 每条任务对应一个可验证的功能点
- 任务粒度适中（1-4小时完成）
- 明确任务编号和名称
- 标注优先级
- 估算工作量
- 标记完成状态

**示例：**
```markdown
# 任务拆分文档

## 任务清单

| 任务ID | 模块 | 任务名称 | 优先级 | 预计工时 | 状态 |
|--------|------|----------|--------|----------|------|
| T1 | 费用申请 | 含税金额必填且手动填写 | 高 | 0.5h | 待开发 |
| T2 | 费用申请 | 去掉造价科审批和打印按钮 | 高 | 1h | 待开发 |
| ... | ... | ... | ... | ... | ... |

## 开发顺序建议
1. 先做不依赖其他功能的修改（如字段必填、隐藏按钮）
2. 再做简单的新增功能
3. 最后做复杂的批量操作和跨模块功能
```

## 注意事项

### 1. 图片处理
- 图片必须按原文档的出现顺序编号
- 图片文件名格式统一：`image_{序号}.png`
- 不要修改图片内容，保持原样提取

### 2. 文档格式
- Markdown格式要规范，便于在IDE中预览
- 标题层级清晰（# > ## > ###）
- 表格对齐美观
- 代码块标注语言

### 3. 需求理解
- 如有不明确的需求，及时与用户确认
- 不要自行脑补需求，不确定的地方标注出来
- 涉及后端接口的地方先确认接口是否存在

### 4. 代码修改
- 完成文档处理后，必须先让用户确认文档是否正确
- 逐条开发，每条完成后等待用户验收
- 不要一次性修改太多文件
